# English loanword expansion — 2026-09-28

**Historical expansion record.** The later [2026-10-01 suffix update](loanword-suffixes-2026-10-01.md) adds `media`, finite attached forms and the school alternative. This page retains the original 50-key count, held decisions and whole-word matching observations.

This dated record follows the [34-key coverage audit](loanword-coverage-audit.md). That audit describes the engine **before** this change, at commit `de2cb93`; its `company` → चोम्पञ् observation is historical. The current change adds `company` → **कम्पनी** and 29 more exact English-spelling keys. Together with the [original 20-word pilot](loanword-review.md), the built-in loanword catalogue now has **50 complete-word keys**, each with one preferred output. The separate 12 Gregorian month names are not included in that count.

The preferred outputs below are **source-assisted project choices for implementation**. An institutional occurrence establishes that a Nepali spelling is used in its source context. It does not establish that the spelling is the only valid one, that the English key always has that sense, or that these keys are the most frequent loanwords. There are still no independently reviewed human loanword labels or population-wide coverage and accuracy estimates. The [earlier audit](loanword-coverage-audit.md) and [pilot](loanword-review.md) retain their original dates, counts, and evidence scopes.

## What typing these words means

- The lookup is for a **complete Roman key**. `convertWord('company')` now returns `{ text: 'कम्पनी', candidates: ['कम्पनी'], ambiguous: false }`; `convertText('company')` and a Nepali-enabled demo field use the same preference. `companyma` and `companyharu` still use the phonetic fallback; this batch does not infer Nepali suffixes from an English stem. The old `company` bug is addressed for the exact key, not for all attached forms.
- `Company` and `COMPANY` currently reach कम्पनी because their capitalization does not contain a reserved Shift sound. Other capitalized words may intentionally differ. `T`, `D`, `S`, `R` and contextual `H` retain the sound controls described in the [typing reference](typing-reference.md#shift-changes-a-few-sounds). The expansion does not broadly lowercase those keys.
- The default `convertText` policy keeps recognizable URL, domain, and email spans literal, such as `company.com` and `company@example.com`. An English-only field should remain unattached or have conversion disabled; SahajLipi does not detect arbitrary English prose. See the [API guide](api.md#links-domains-and-email-addresses).
- Each new key has **one candidate**. Source-observed variants are research notes, not automatically offered dropdown alternatives. A developer may provide ordered alternatives or a different preference with `createEngine({ entries })` as described in the [API reference](api.md#core-engine).

This is a **coverage change for selected exact keys**, not an English pronunciation model or a general spelling correction. More mappings can also create false automatic conversions in mixed Nepali/English fields. The [seed benchmark](benchmarks.md) and Node tests are software regression checks against project-authored expectations. They are not independent human language labels or evidence of improved typing accuracy. A future evaluation should use a frozen, separately reviewed set with denominators for preferred output, acceptable candidates, and false conversions across ordinary Roman Nepali, loanword, and mixed-text slices.

Sources were checked on **2026-09-28**. We record short observations and links, not bulk source content. ## Reproduce the code observations

From the repository root **after** this expansion, run:

```sh
node --input-type=module - <<'JS'
import { convertWord, convertText } from './src/index.js';
for (const key of ['company', 'Company', 'COMPANY', 'companyma', 'ambulance', 'router', 'website', 'speaker', 'train', 'fax', 'wallet', 'share']) {
  console.log(key, convertWord(key));
}
console.log(convertText('company company.com company@example.com'));
JS
npm test
npm run benchmark -- --check
```
